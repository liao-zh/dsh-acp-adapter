# ACP sidecar 数据库体积增长到 457 MB（无保留策略）

- 记录日期：2026-11-17
- 状态：**已查明、未清理**（用户决定先留笔记，暂不动手）
- 环境：DSH `0.2.2-rc.3` / Windows 11 / `@zaimokuza/dsh-acp-adapter` `0.2.2-rc.3.1`（上游 npm 版）
- 一句话：`~/.dsh/dsh-acp/sidecar.sqlite` 是适配器自己的持久化库，457 MB 里 **381.7 MB 是 `activity_journal` 的逐条活动日志**；
  插件**没有任何保留/裁剪策略**，从 10-22 首次安装起一路累积，换插件版本也不会重建或清空。

## 一、这是什么

插件源码 `lib/persistence/sidecar.js`：

- 路径：`<dshHome>/dsh-acp`（第 4 行注释），单库 `<root>/sidecar.sqlite`；
- 引擎：`node:sqlite` 的 `DatabaseSync`（Node ≥22.13 免 flag）；
- `journal_mode=WAL`、`synchronous=NORMAL`、`busy_timeout=5000` ⇒ 旁边常驻 `-wal` / `-shm`；
- 权限：目录 `0700`，库与 `-wal`/`-shm` `0600`（打开后显式 chmod 兜底）；
- 所有表都是 `STRICT`。

**归属确认**：本机该目录创建于 `2026-10-22 11:48`，正是首次安装本插件、校准 CodeBuddy 那天
（见工作区 `notes/2026-10-22-操作-DSH-ACP安装与CodeBuddy校准.md`）。DSH 宿主自身不用这个路径。

## 四、为什么不会自己变小

搜过整个 `sidecar.js`：**`activity_journal` 与 `audit` 没有任何 `DELETE` / TTL / maxRows / 裁剪 / evict 路径**。
现存的 `DELETE FROM` 只针对三类按会话粒度的小表：

- `dispatch_ledger`（`stmtClearDispatch` / `stmtDeleteDispatch`）
- `mode_intents`
- `member_model_selections`

唯一与"丢弃"沾边的是 **audit 的内存队列满时的告警**
（`dropping non-approval audit records`），那是写入队列，不是库内清理。

所以体积随使用时间**线性增长**，且上游没有提供「清理历史活动」的用户入口。

## 五、直接删掉的后果（评估）

| 删掉的东西 | 后果 | 可接受性 |
|---|---|---|
| `activity_journal` + `audit` | 只是历史活动/审计展示没了 | ✅ 基本无损 |
| `bindings`（63 行） | 「DSH 会话 ↔ ACP 会话」绑定丢失 ⇒ **已有 ACP 会话的 Agent 上下文续不上**（会被当作需要重连/新建） | ⚠️ 有感知但不严重 |
| 整个 `~/.dsh/dsh-acp/` | 上述全部 | ⚠️ 同上 |
| **DSH 自己的会话历史** | **完全不受影响**（`~/.dsh/sessions/*.jsonl.zst` 与这里无关） | ✅ |

对比 `notes/2026-11-15-跨后端切换弹窗无法关闭.md` 那种会话级死锁：**这条代价小得多**，
最坏情况是 ACP 会话上下文续不上，不会让会话打不开。

## 六、清理选项（代价从低到高，本次**未执行**）

1. **先备份再删**：整份 `~/.dsh/dsh-acp/` 复制到别处 → 删原目录 → 观察几天 → 无异常再删备份。
   最稳，出问题可整份还原。
2. **只删活动日志、保留绑定**（推荐）：事务内 `DELETE FROM activity_journal;` 再 `VACUUM;`
   ⇒ 预计回收约 425 MB，`bindings` 等小表保留，ACP 上下文续聊不受影响。
3. **只 `VACUUM`**：能回收索引与空闲页，但主因是数据行本身 ⇒ 收益有限。
4. **不处理**：457 MB 只是占盘，不影响功能。

⚠️ **任何方案都必须在「DSH 完全退出」后做**：库是 WAL 模式，插件运行时会持有句柄并周期性 checkpoint，
边写边删/边 VACUUM 有损坏风险。判据：确认没有 `dsh` / 桌面版进程还在用这个 profile。
（桌面版与 `dsh web` 都可能同时打开同一个库 —— 远端那台有自己的 `~/.dsh`，互不影响。）

## 七、复现命令

只读查库（`node:sqlite`，不会写入）：

```js
const { DatabaseSync } = require('node:sqlite')
const db = new DatabaseSync(process.env.USERPROFILE + '/.dsh/dsh-acp/sidecar.sqlite', { readOnly: true })
// 各表行数
for (const { name } of db.prepare("SELECT name FROM sqlite_master WHERE type='table' ORDER BY name").all())
  console.log(name, db.prepare(`SELECT COUNT(*) c FROM "${name}"`).get().c)
// 按对象（表/索引）占页
console.log(db.prepare('SELECT name, SUM(pgsize) b FROM dbstat GROUP BY name ORDER BY b DESC').all())
db.close()
```

文件本身：

```powershell
Get-ChildItem "$env:USERPROFILE\.dsh\dsh-acp" -Force | Select-Object Name, Length, LastWriteTime
```
